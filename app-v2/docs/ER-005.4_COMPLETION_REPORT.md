## 1. Repository analysis

Reviewed: 12 Supabase migrations, Event/Venue/Auth models, RLS, services, providers, routing, and documentation (`ARCHITECTURE_ROADMAP.md`, `PLATFORM_ARCHITECTURE_FOUNDATION.md`, `AI_CONTEXT.md`, `BACKLOG.md`, `PROJECT_STATE.md`).

## 2. Current architecture

```
Screens → Features → Repositories → Datasources (local | supabase) → PostgreSQL + Storage
```

- Events, Import, Contributor flow, Auth, Search operational
- Community, native ticketing, organizers table: **not implemented** (documented only)

---

## 3. Identified architectural risks

| Risk | Severity |
|------|----------|
| Single `artist_id` / `genre_id` vs multi-artist lineup | High |
| Organizer not persisted | High |
| Community as parallel systems | High |
| `status` column overload (editorial vs operational vs ticket) | Medium |
| Documentation drift (`database.md`, pipeline docs) | Medium |
| `ticket_url` → native ticketing migration | Medium |
